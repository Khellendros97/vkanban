### 关键实现细节

**数据模型**
- SQLite 全局 DB（`~/.vkanban/data.db`），WAL + busy_timeout=5000
- tasks 表: 12 列（id, project_name, project_path, content, output, status, error_code, claimed_at, created_at, updated_at, started_at, finished_at）
- CHECK 约束: status 枚举 / error_code 枚举 / content≤64KB / output≤1MB
- 索引: idx_tasks_project / idx_tasks_status
- ID: nanoid(12)，字符集 [A-Za-z0-9_-]

**状态机 (5 状态)**
- pending → running → done / failed / cancelled
- 所有转移通过 CAS `WHERE status=?` + affected rows 判定

**进程模型**
- 父进程 spawn supervisor（Bun subprocess, unref）
- supervisor claim（`WHERE claimed_at IS NULL` 排他）
- supervisor spawn pi → await exit → 兜底
- 父进程 5s claim 监控（`VKANBAN_CLAIM_TIMEOUT_MS` 可配）

**跨平台**
- 路径: 全程 `path.resolve` + `path.isAbsolute`，禁止 POSIX 化
- kill: tree-kill npm 包统一
- detach: POSIX `detached: true` / Windows `windowsHide`

### 已知限制（v0 范围内可接受）

- `registry.json` 无并发锁（人工不并发 init）
- 无任务超时策略
- 无 Webhook / 通知
- `pi` 扩展本身不在本 repo 中实现

## Review-0001

### 审查结果
需要整改

### 总体评价
实现覆盖了基础数据模型、CAS claim、supervisor 兜底和主要内部流程，49 个测试通过说明底层路径有一定保障。但当前实现与 spec v0.4 的公开 CLI 契约和 cancelled 状态机存在关键偏差，测试也主要验证了内部子命令而不是设计规定的用户入口，不能视为 v0.4 合格交付。

### 问题列表

#### Blocker
1. 公共 CLI 入口未按 spec 实现：设计要求 `vkanban -p <name> <content...>`、`vkanban -t <id>`、`vkanban -t <id> -s <output>`、`vkanban -t <id> --fail <reason>`、`vkanban -t <id> --cancel`、`vkanban -t <id> -v`；当前实现为 `dispatch/query/writeback/fail/cancel/wait` 子命令，真实用户按 spec 调用会失败。涉及 `src/cli.ts`、`src/commands/*.ts`，测试也全部使用子命令，未覆盖公开契约。
2. `cancelled` 状态实现错误：`casRunningToCancelled()` 复用 `casRunningToFailed()`，实际写入 `status='failed', error_code='cancelled'`，违反状态机 `running→cancelled`，也会导致查询、列表、等待输出语义错误。涉及 `src/tasks.ts`、`src/commands/cancel.ts`；现有 `tests/e2e/cancel.test.ts` 只断言 `error_code`，漏测 `status`。
3. supervisor 启动参数不满足跨平台/生命周期约束：dispatch 中 `Bun.spawn(["bun", "run", supervisorEntry])` 未设置 POSIX `detached: true` / Windows `windowsHide: true`，且依赖 `bun` 在 PATH 中；这与 spec 要求的 detach/unref 和跨平台稳定性不一致。涉及 `src/commands/dispatch.ts`。
4. `resolveCliPath()` 不保证绝对路径，也缺少 `process.execPath` 兜底；`resolveSupervisorEntrypoint()` 只返回 `supervisor.ts`，未按 spec 检查 override 绝对路径、未支持发布态 `supervisor.js`，也未在找不到入口时抛错。涉及 `src/paths.ts`。
5. project name 校验允许 `..`，违反 spec 明确禁止 `..` 的约束。涉及 `src/registry.ts`；现有单测只覆盖空串和空格，未覆盖 `..`。

#### 建议
1. `src/db.ts` 与 `src/commands/dispatch.ts` 用字符串拼接生成 `data.db` 路径，建议统一改为 `path.join(resolveVkanbanHome(), "data.db")`，保持 native path 约束。
2. supervisor 直接 `new Database(dbPath)` 未设置 `PRAGMA busy_timeout=5000`，并发写回/兜底时可能出现锁冲突；建议每个连接初始化必要 PRAGMA。
3. `remove` 只更新 `registry.json`，未维护 `projects.removed_at`；若继续保留 `projects` 表，应同步写入，否则建议明确表为未使用审计预留并调整 spec/测试。
4. dispatch 在 supervisor 未 claim 时只向 stderr 打 warning JSON，没有按 spec 始终向 stdout 打印 `task_id`，调用方机器解析会不稳定。
5. E2E 未覆盖真正 dispatch happy path（spawn supervisor → fake pi → writeback）、公开 CLI 简写入口、claim timeout stdout 契约、cancelled 状态、发布态路径解析和 name=`..` 等关键边界。
